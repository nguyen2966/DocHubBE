We need to update the DocHub auth + workspace invitation workflow across BE and FE.

Goal:
Implement a safer email verification flow that prevents an attacker who only steals the verification URL from activating the account and starting a session before the real user.

Product requirement:
- Clicking the verify button in email should still activate the account and start a session for the legitimate user.
- To satisfy this safely, bind verification auto-login to the browser that started signup using a temporary signup nonce cookie.
- If the verification token is valid but the signup nonce is missing or mismatched, do NOT verify the user, do NOT consume the token, and do NOT start a session.

Also preserve workspace invitation behavior:
1. Registered user + valid session:
   - Click Join Workspace email button.
   - Accept invitation immediately.
   - Redirect to /workspaces/:workspaceId/documents.

2. Registered user but signed out:
   - Click Join Workspace email button.
   - Redirect to sign in page.
   - After sign in, accept invitation.
   - Redirect to /workspaces/:workspaceId/documents.

3. Unregistered user:
   - Click Join Workspace email button.
   - Redirect to /signup?invitationToken=...
   - Register.
   - Verify email.
   - Verification should start session only if signup nonce matches.
   - After verification/session start, redirect to invited workspace page:
     /workspaces/:workspaceId/documents
   - Normal non-invited register should redirect to welcome page.

Important security model:
- invitationToken: only controls invite flow; never starts an auth session.
- email verification token: verifies email; should not start session by itself.
- signupNonce: proves the current browser initiated the signup; required for verification auto-login.
- verification token + valid signupNonce = verify account + start session.
- verification token without signupNonce = reject safely, keep token valid for real browser.

Acceptance criteria:

A. Normal register:
1. User signs up normally.
2. BE creates signupNonce cookie.
3. Email link points to FE /verify-email#token=...
4. Same browser opens email link.
5. FE POSTs token to BE.
6. BE validates token + signupNonce.
7. BE verifies user and starts session.
8. FE redirects to /welcome?status=success.
9. Raw access/refresh tokens are not returned in JSON.

B. Attacker steals verification link:
1. Attacker opens /verify-email#token=... in a different browser.
2. Attacker has no signupNonce cookie.
3. BE returns 403 or safe error.
4. Token is NOT consumed.
5. User can still open same link from original signup browser and succeed.

C. Registered invited user with active session:
1. Click invitation email.
2. BE accepts invitation.
3. Redirect to /workspaces/:workspaceId/documents.

D. Registered invited user signed out:
1. Click invitation email.
2. Redirect to /invitations/:token/accept.
3. FE redirects to /login?next=/invitations/:token/accept.
4. After login, FE accepts invitation.
5. Redirect to /workspaces/:workspaceId/documents.

E. Unregistered invited user:
1. Click invitation email.
2. Redirect to /signup?invitationToken=...
3. Register with same invited email.
4. BE validates invitationToken belongs to that email.
5. BE creates signupNonce cookie and sends verification email.
6. User opens verify email in same browser.
7. BE validates token + signupNonce.
8. BE verifies email, claims pending invitation, starts session.
9. FE redirects to /workspaces/:workspaceId/documents, not welcome.

F. Invalid invitation email mismatch:
1. User opens /signup?invitationToken=... but registers with a different email.
2. BE rejects register with clear error.

G. Already registered but unverified invited user:
1. User clicks invitation email.
2. Do not send them into login loop.
3. Show verify-required page or route where they can resend verification.

Implementation notes:
- Keep code style consistent with current NestJS + React TypeScript style.
- Do not rewrite unrelated modules.
- Do not change workspace permission logic.
- Do not make invitation token start a session.
- Do not consume verification token when signup nonce is missing/mismatched.
- Prefer httpOnly cookie for signupNonce.
- Use SameSite=Lax so the cookie works for normal top-level email-link navigation.
- Use Secure=true only in production.
- Make Redis token consumption atomic after nonce validation.
- Remove token from frontend URL hash after reading it.
